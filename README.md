# Hu Pai Online

一个基于 Node.js、Express 和 WebSocket 的多人在线诈唬出牌小游戏。玩家可以创建房间、邀请朋友加入，并在浏览器中实时同步对局状态。

## 功能

- 创建房间并生成房间码
- 输入昵称后加入多人对局
- 大厅阶段允许修改昵称，开局后锁定
- 基于 WebSocket 的实时同步
- 支持部署到公网服务器后进行多人联机

## 游戏规则

### 基础设定

- 支持 `2-8` 名玩家同局
- 使用一副 `54` 张牌：
  - 四种花色的 `A-K`
  - 大王和小王各一张
- 大小王属于万能牌，在质疑结算时可视为任意声明点数

### 开局

- 房主创建房间时设置最大人数
- 所有玩家加入前都必须输入昵称
- 至少 `2` 名玩家后，房主才可以开始游戏
- 开始后系统洗牌并尽量平均发牌
- 开局后昵称不能再修改

### 回合流程

- 每一轮由当前首家先出牌，并声明一个点数作为“本轮牌面”
- 首家可以打出任意自己手里的牌，但其他玩家只能看到你“声明出了几张、声明的点数是什么”，看不到真实牌面
- 本轮后续玩家如果继续出牌，声明点数必须和本轮牌面一致
- 玩家轮到自己时有三种选择：
  - 出牌
  - 不出
  - 质疑上一手

### 出牌

- 每次至少出 `1` 张牌
- 只能打出自己当前真实持有的牌
- 实际打出的牌可以和声明不一致，因此可以诈唬
- 如果你打出的是真牌，也就是所有牌都符合声明点数，或者是大小王，那么这手牌在结算时会被判定为真实

### 不出

- 只有在桌上已经存在上一手时，后续玩家才能选择“不出”
- 当前这一轮的首家不能直接“不出”
- 如果轮到你响应上一手，而你在 `20` 秒内没有操作，系统会自动判定为“不出”
- 如果其余玩家依次都选择“不出”，最后一次成功出牌的玩家赢得这一轮：
  - 桌面上的牌进入弃牌堆
  - 该玩家成为下一轮首家
  - 下一轮重新声明新的牌面点数

### 质疑

- 只有当前轮到你、且桌上有可响应的上一手时，才能发起质疑
- 不能质疑自己刚打出的牌
- 发起质疑后，系统会短暂公开上一手的真实牌面，然后自动结算

### 质疑结算

- 若上一手的所有牌都满足以下条件，则质疑失败：
  - 牌点数与声明一致
  - 或该牌是大王 / 小王
- 质疑失败时：
  - 质疑者收走桌面上的所有牌
  - 上一手出牌者成为下一轮首家
- 若上一手存在任意一张既不是声明点数、也不是王的牌，则质疑成功
- 质疑成功时：
  - 上一手出牌者收走桌面上的所有牌
  - 质疑者成为下一轮首家

### 胜负与排名

- 玩家手牌出完后，会先进入待确认完成状态
- 如果这名玩家在后续结算中没有重新收回牌，就会正式进入完成顺序
- 当场上只剩 `1` 名仍持有手牌的玩家时，对局结束
- 排名按出完手牌的先后顺序确定，界面会显示完整名次

## 本地启动

```bash
npm install
npm start
```

默认监听：

- `HOST=0.0.0.0`
- `PORT=3000`

浏览器访问 `http://localhost:3000`

如果需要显式指定地址和端口：

```bash
HOST=0.0.0.0 PORT=3000 npm start
```

Windows PowerShell:

```powershell
$env:HOST="0.0.0.0"
$env:PORT="3000"
npm start
```

## 手动验证建议

当前没有自动化测试。修改后建议启动服务，并至少用多个浏览器标签页手动验证以下场景：

- 创建房间并邀请其他玩家加入
- 房主开局并确认玩家收到手牌
- 首家声明点数后，其他玩家执行出牌、不出、质疑
- 验证质疑成功和质疑失败两种结算
- 验证全员不出后进入新一轮
- 刷新或断开连接后确认房间状态同步正常

## 公网部署

服务端是单实例内存房间模型，部署时要求所有玩家连接到同一个实例。

### 环境变量

- `HOST`: 监听地址，默认 `0.0.0.0`
- `PORT`: 监听端口，默认 `3000`

### 反向代理要求

- 需要把 HTTP 请求转发到 Node 服务
- 需要保留 WebSocket Upgrade 头，否则实时同步无法建立
- 如果由 HTTPS 终止，前端会根据当前页面协议自动使用 `wss://`

## 当前限制

- 房间和对局状态保存在进程内存中，服务重启后会丢失
- 不支持多实例横向扩展
- 不包含持久化存储、断线重连恢复或 P2P 直连能力
